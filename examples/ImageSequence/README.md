# ImageSequence：发送可取消的 RGB565 测试图序列

[ImageSequence.ino](ImageSequence.ino) 用同一个 RAM 缓冲生成并发送三张彩色渐变/棋盘测试图，演示分块上传、帧间等待、进度和取消。它是有限的静态图片序列，不采集相机，也不提供视频流。

## 硬件和 App 前提

- 使用有 BLE 的 ESP32 系列开发板，无需相机、显示屏、文件系统或 PSRAM；ESP32-S2 没有 BLE，不适用。
- 安装本库及兼容的官方 Arduino-ESP32 3.x Core。本库已经包含启用 CoC 的 NimBLE，不要另外初始化蓝牙栈。
- App 需支持 IMAGE 和 **大端 RGB565**，订阅控制通知 `0xFFC4`，打开 **IMAGE CoC PSM `0x0082`**。`READY` 只表示控制通道就绪。

## 可调整配置

默认配置可以直接用于测试，不需要修改 GPIO。

| 常量 | 默认值 | 用途 |
| --- | --- | --- |
| `kWidth` / `kHeight` | 64 / 48 | 每张图片尺寸，RGB565 缓冲占 6144 字节 RAM |
| `kFrameCount` | 3 | 一次请求发送的图片数 |
| `kFrameGapMs` | 2000 | 上一帧本地完成后，到下一帧尝试开始的间隔 |
| `kChannelWaitMs` | 30000 | 等待 IMAGE 通道或前一帧排空的最长时间 |

修改尺寸时，当前渐变算法要求宽、高至少为 2，并要重新核算 RAM。修改帧数时，也应同步调整端点描述和提示中的“三张”说明。`makeFrame()` 是替换测试图生成逻辑的位置。

## 上传和使用步骤

1. 在 Arduino IDE 打开本目录 `.ino`，选择实际开发板和容量足够的应用分区，USB 上传。
2. 打开 **115200 波特率**串口监视器，确认启动和 IMAGE 支持结果没有错误。
3. 在 App 连接 `Deotaland-ImageSequence`，订阅控制通知并打开 IMAGE CoC。
4. 输入 `b`，或从 App 调用 `camera0=true`，启动一组三张测试图；输入 `x` 可中途停止。
5. 输入 `?` 查看进度和后台 IMAGE 状态，并在 App 检查实际收到的三张测试图。

## 串口和 App 操作

| 操作 | 行为 |
| --- | --- |
| 串口 `b` / `B` | 请求一组图片；控制连接未就绪时不会启动 |
| 串口 `x` / `X` | 停止后续帧，并取消当前上传 |
| 串口 `?` | 报告控制状态、序列是否活动、本地完成帧数、上传器及 IMAGE 状态 |
| App 的 `camera0=true` | 启动一组测试图；该端点不接入实体相机 |
| App 的 `camera0=false` | 取消序列 |

忙时重复启动会提示已有活动序列，不叠加请求。断连会取消旧序列，重连后需要重新启动。

## 预期现象和生命周期

每帧结束会输出 `Frame ... local result: ESP_OK`，三帧结束后输出 `Sequence complete locally.`。上传较慢时还会约每秒输出一次已被本地接受的字节数；快速的小图可能直接完成。

同一缓冲在上传借用期间不会被重写。下一帧除等待默认 2 秒外，还要等待前一帧后台排空，因此实际帧间隔可能更长。通道等待或上传超时会停止序列。

图片和 END 被本地接受后，后台仍可能发送失败。前一帧出现后台 `FAILED` 时会停止自动发送后续帧并报告 `last_error`；最后一帧的后台结果可用 `?` 查看 `IMAGE state/queued/last_error`。用户可以手动再次输入 `b` 发起新一组尝试。

取消后程序仍轮询 END 清理；已经本地接受的字节不能撤回。**本地完成帧数、`Completed` 和 `ESP_OK` 都不是 App 收图或解码的 ACK**，最终结果要在 App 独立确认。
